Case 01 · Service extraction

세 레거시 백엔드의 구독 기능을 하나씩 전용 서비스로 떼어냈어요.

실제 운영 트래픽을 받는 전용 서비스로 API 9개를 옮겼어요. 세 저장소에 흩어진 호출 경로와 계약 차이를 좁힌 뒤 전용 서비스의 API를 직접 구현하고, 운영에서 전환 결과를 검증했어요.

  • 역할 이전 범위 선정 · 계약 비교 · 구독 서비스 API 구현 · 운영 검증
  • 결과 9개 API 전환 · 클라이언트 변경 0
  • 상태 일부 운영 트래픽 전환 완료

Case 02 · Performance

30초 넘게 타임아웃되던 응답을 1초 미만으로 줄였어요.

결제 이력을 통째로 미리 읽으면서도 정작 응답을 만들 때는 다시 조회하고 있었어요. 그 선조회를 걷어내고 집계를 DB로 옮겼어요. 같은 계정과 데이터로 배포 전후를 반복 측정했고, 데이터를 받지 못하던 앱 화면이 정상 노출되는 것까지 확인했어요.

  • 원인 쓰이지 않는 결제 원본 선조회 + 도메인 메서드의 재조회
  • 결과 모든 측정 1초 미만 · 읽어 들인 행 약 1/1,000
  • 영향 30초 이상 응답 실패 해소 · 앱 화면 복구

Case 03 · Data integrity

리뷰를 고치고 보상을 회수해도 원장과 이력이 같은 값을 가리키게 했어요.

복제 지연, 수정 중 리뷰의 한도 오염, 재계산 동시성, 교차 저장소 원장 반영까지 정합성 경계를 하나씩 따라가 해결했어요. 상태 플래그가 아니라 원장의 순변화를 진실로 삼았어요.

  • 불변식 같은 리뷰 상태면 몇 번 재계산해도 최종 잔액과 이력이 같다
  • 해결 정합성 경계 4건 · 음수 offset 원장 · 리뷰 단위 잠금
  • 경계 다른 저장소를 하나의 transaction처럼 가장하지 않음

Working principles
